# Plan for #1: Add GET /api/vehicles listing distinct vehicle IDs

## Goal
Clients get `GET /api/vehicles` returning the distinct `vehicleId` values of all stored runs,
sorted ascending, as a JSON string array. Nothing about runs, validation, or the web page changes.

## Files to change (confirmed / plausible / open)
- **confirmed** `src/runs.ts` — `RunStore` (line 49) holds the only run data; it has `list()`/`get()`/`create()`
  but no distinct-vehicle accessor. Add `vehicleIds(): string[]` next to `list()` so domain logic stays out of routes
  (`.github/instructions/src.instructions.md` line 7).
- **confirmed** `src/app.ts` — routes live here; add `GET /api/vehicles` above `/api/runs/:id` (line 30).
  Placement is cosmetic, `/api/vehicles` cannot be captured by `/api/runs/:id`.
- **confirmed** `test/app.test.ts` — `buildApp()` (line 7) seeds `SEED_RUNS`; a second app with an empty
  `RunStore()` is needed for the empty-store case.
- **confirmed** `README.md` — the ticket requires the endpoint to be listed. There is currently **no** endpoint
  list in the README (only the env-var table, lines 43-49). A short "API" section has to be created.
- **plausible** `public/index.html` / `e2e/smoke.spec.ts` — not touched: the ticket asks for an API only,
  the page never calls `/api/vehicles`.
- **open** none.

## Tests
- `test/app.test.ts`, new `describe("vehicles api")`:
  - seeded store returns `["WVW-1001","WVW-2042","WVW-3310"]` — distinct (WVW-1001 appears twice in `SEED_RUNS`) and sorted
  - empty store returns `[]` with status 200
  - a run created via `POST /api/runs` shows up in the list

## Environment contract
No new variable. `src/config.ts` is untouched, so `k8s/configmap.yaml` and the README env table stay as they are.

## Risks
- Sort order: plain `Array.prototype.sort()` is lexicographic on strings. The seeded IDs are ASCII, so
  ascending and lexicographic agree. No locale-aware sort (`localeCompare`) to keep the result stable across runners.
- Pipeline: only `test` (unit) can go red from this change. `deploy-kind` rollout/stability/smoke/browser are
  unaffected — no manifest, no config, no page change.
- Route order in `src/app.ts`: putting the route after `/api/runs/:id` would still work, but the new route
  must not be registered after the error handler (line 42) or it would never match.

## Open questions
1. README placement — no blocking question: an "API" section goes in front of "Environment contract".
2. Empty-store shape — `[]` and HTTP 200, not 404. `GET /api/runs` on an empty store behaves the same way.
