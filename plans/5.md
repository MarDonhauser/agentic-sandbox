# Plan for #5: Enable the metrics endpoint in the deployment

## Goal
Operations can scrape runtime metrics from the deployed pod. The app already has a
metrics listener; only the deployment has it switched off. Nothing about the JSON API,
the web page, or the existing `/health` behaviour changes.

## Files to change (confirmed / plausible / open)
- `k8s/configmap.yaml` — confirmed. Line 8 holds `METRICS_ENABLED: "false"`; that is the switch the
  ticket calls "switched off in the deployment".
- `k8s/deployment.yaml` — confirmed. `spec.template.spec.containers[0].ports` (lines 21-23) has only
  `http`/3000. The ticket wants a second container port named `metrics`.
- `README.md` — confirmed. The ticket asks for documentation of how to reach the metrics endpoint.
- `src/server.ts` — plausible. It is listed in `AGENTS.md` as "process start, logging, optional metrics
  listener", so the listener already exists and no source change should be needed.
- `k8s/service.yaml` — open. The ticket says "container port", not "service port". Prometheus in this
  sandbox does not exist, so leaving the Service untouched should be fine.

## Tests
None. This ticket touches `k8s/` and `README.md` only; there is no unit or browser test for manifests.
The pipeline's rollout, stability, smoke and browser steps are the test.

## Environment contract
Corrected after the first pipeline run. `src/config.ts:21-30` requires `METRICS_PORT` as soon as
`METRICS_ENABLED=true`, and rejects a value equal to `PORT`. `src/server.ts:11-17` turns that into
`process.exit(1)`. A `containerPort` in `k8s/deployment.yaml` sets no environment variable, so the
ConfigMap must carry `METRICS_PORT: "9090"` as well, and the README table row plus the metrics
paragraph must name the same port.

## Risks
- The metrics port number is not given in the ticket; picking one that clashes with `PORT` (3000) would
  break the app. Using 9090 avoids that.
- `k8s/` changes cannot be verified locally (`verify-change` step 4). Only the pipeline proves it.

## Open questions
1. Which port number should `metrics` use? Not stated in the ticket; going with 9090 (the usual
   Prometheus default) and documenting it.
2. Should the Service expose the metrics port too? Ticket says container port only; leaving Service as is.

## Deviation after run 35707761930 (stability failed)
Flipping `METRICS_ENABLED` alone crashed the pod:
`startup failed: invalid configuration ... METRICS_PORT is required when METRICS_ENABLED=true`.
The plan above under-read the environment contract: it checked that `METRICS_ENABLED` exists in the
ConfigMap instead of reading `src/config.ts`. Fix added `METRICS_PORT: "9090"` to the ConfigMap.
