# Plan for #9: Add GET /api/runs/summary with average CO2 per vehicle

## Goal
One row per vehicle instead of one row per run: `GET /api/runs/summary` returns
`[{ vehicleId, runs, avgCo2GramsPerKm }]`, sorted by `vehicleId`, average rounded
to one decimal. Nothing else changes: `/api/runs`, `/api/runs/:id`, `POST /api/runs`
and the web page keep their behaviour.

## Files to change (confirmed / plausible / open)
- **confirmed** `src/runs.ts` — `RunStore` (line 49) owns the in-memory data and
  already exposes `list`/`get`/`create`. `.github/instructions/src.instructions.md`
  puts domain logic here, so the aggregation goes into a new `RunStore.summary()`.
- **confirmed** `src/app.ts` — routes live here. `app.get("/api/runs/:id")` is
  registered at line 30; the new route must be registered **before** it, otherwise
  Express matches `summary` as `:id` and answers 404.
- **confirmed** `test/app.test.ts` — supertest suite against `createApp`; the
  seeded store (`SEED_RUNS`, `src/runs.ts:79`) is the fixture for the new test.
- **confirmed** `README.md` — has no endpoint list today; the ticket asks for one,
  so a short "API" section goes above the environment contract table.
- **plausible** `public/index.html` — fetches `/api/runs` only (lines 40, 51). The
  ticket does not ask for a UI change, so the page stays untouched and `e2e/` is
  unaffected.
- **open** none.

## Tests
- `test/app.test.ts`: new `describe("runs summary")` with
  - the seeded aggregate: `WVW-1001` 2 runs / 125.2, `WVW-2042` 1 / 97.2,
    `WVW-3310` 1 / 104, sorted by `vehicleId`
  - `summary` is not read as a run id (status 200, not the 404 body of `:id`)
  - a POST changes the aggregate (count and average of the new vehicle)
- Route order is proven by the second test: with the route registered after
  `:id` it fails with the 404 body.

## Environment contract
No new variable. `src/config.ts` unchanged, so `k8s/configmap.yaml` and the README
table stay as they are.

## Risks
- **Route order.** Registering after `/api/runs/:id` gives a green build but a
  broken endpoint (404 `run not found`, id `summary`). Covered by a test.
- **Rounding.** `WVW-1001` averages to exactly 125.15, a decimal tie. The ticket
  does not name a tie rule. `Math.round(avg * 10) / 10` yields 125.2 here because
  the stored double is 125.15000000000000568…, above the tie. Recorded in the PR.
- **Output shape.** `avgCo2GramsPerKm` is a number, so `104.0` serialises as `104`.
  Formatting to a fixed-decimal string would break the `runs` numeric contract.
- Pipeline: unit only. Rollout, stability, smoke and browser are unaffected — no
  manifest and no page change.

## Open questions
None blocking. Two decisions taken and written into the PR: tie rounding is
half-up via `Math.round`, and the average is a JSON number, not a string.
