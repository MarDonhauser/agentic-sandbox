# Plan for #2: Reject CO2 values outside 0 to 500 g/km

## Goal
`POST /api/runs` rejects `co2GramsPerKm` below 0 or above 500 with HTTP 400 and the
detail `co2GramsPerKm must be between 0 and 500`. Everything else stays: 0 and 500 are
accepted, the existing type check, the response shape, and the seeded runs are untouched.

## Files to change (confirmed / plausible / open)
confirmed
- `src/runs.ts:37-39` `validateNewRun` — only place that validates `co2GramsPerKm`.
  Add the range check after the type check. Read.
- `test/app.test.ts:62-66` `"rejects invalid input with details"` sends
  `co2GramsPerKm: "x"` and asserts `toHaveLength(3)`. If the range check also fires for a
  non-number, this test goes to 4 details and fails. The range check must run only when the
  value is a number. Read; the test is not edited.
- `test/app.test.ts` — new cases for below, above, and both boundaries. Read.

plausible (read, no change needed)
- `src/app.ts:36-51` route and error mapping; `ValidationError` already maps to 400 with
  `details`, so no route change.
- `public/index.html:51-53` posts the form and prints `data.details` into the status
  paragraph, so the new message reaches the user without a page change.
- `src/runs.ts:53-55, 79-84` `SEED_RUNS` are inserted through `RunStore.create`, not through
  `validateNewRun`, and all four values are 97.2-131.9, so seeding cannot break.
- `e2e/smoke.spec.ts:16` fills `123.4`, inside the range, so the browser check is unaffected.

open
- none. No `k8s/` or `README.md` hit: `grep -rn -i co2 k8s README.md` returns only the README
  intro sentence.

## Tests
- `test/app.test.ts`: `-5` -> 400 with the message; `9999` -> 400 with the message;
  `0` -> 201; `500` -> 201.

## Environment contract
No new or changed variable in `src/config.ts`, so `k8s/configmap.yaml` and the README table
stay as they are.

## Risks
- unit: the existing 3-details assertion breaks if the range check runs on a non-number.
- rollout / stability / smoke: no config, image, or manifest change, so unaffected.
- browser: `e2e/smoke.spec.ts` only adds an in-range run; unaffected.
- Range bounds are inclusive; `Number.isFinite` keeps `Infinity` out with the range message
  rather than the type message.
