# Plan for #3: Delete run

## Goal
Add a DELETE endpoint for measurement runs so a wrong record can be removed, while preventing deletion of in-progress runs and returning the documented 404/409 responses. This does not change the existing run model or environment config.

## Dependencies (confirmed / plausible / open), each with change: yes | no
- confirmed: `src/runs.ts` `RunStore` — needs a delete operation and status-aware checks; change: yes
- confirmed: `src/app.ts` — add `DELETE /api/runs/:id` and map validation/logic to HTTP codes; change: yes
- confirmed: `test/app.test.ts` — add tests for existing run deletion, unknown ID, and in-progress rejection; change: yes
- plausible: `public/index.html` — may later add a delete button, but the ticket is API-only and no UI requirement is stated; change: no
- open: none

## Tests
- `test/app.test.ts`: delete an existing run and verify it disappears from `GET /api/runs`
- `test/app.test.ts`: delete an unknown ID and expect 404 with `{ error: "run not found", id }`
- `test/app.test.ts`: attempt to delete a run whose status is `running` and expect 409 with `{ error: "run is in progress" }`

## Environment contract
- No environment changes; no config or manifest updates needed.

## Risks
- Deleting a run must be consistent with the in-memory store and all API consumers.
- Incorrect status checks could allow deleting active runs or block valid planned/done deletions.
- The main pipeline risk is unit-test regressions; there is no browser or K8s change.

## Open questions
1. None.

## Decisions
1. No open questions; the ticket is clear and API-only.
